# DocAssist

Рабочее место мастера студенческого отряда: веб-приложение для ускорения и автоматизации работы с документами РСО
(Российских студенческих отрядов). Набор отдельных «приложений» на общем ядре. Работает **локально и офлайн**: данные
хранятся на устройстве. По желанию — **Google Диск и Google Таблицы** (только на сайте и в установленном приложении):
данные идут из браузера прямо в Google-аккаунт человека, разработчику не отправляется ничего.

- Первое приложение — **«Проверка анкет»**: загружаете таблицу анкет (файлом или через Ctrl+V), приложение находит
  ошибки, подсказывает, как их исправить, и собирает исправленную таблицу.
- Оформление по фирменному стилю РСО: синий и белый, шрифты Akrobat и LIBRARY 3 AM (если не установлены — встроенные
  Exo 2 и Oswald). Что найдено в официальных материалах и как применено — [docs/RSO-BRAND.md](docs/RSO-BRAND.md).
- **«Личные дела»**: ручной ввод всех данных бойца в базу людей, личная папка (фото, сканы, достижения, характеристика) и
  оформление перевода — документы Word, таблица Excel со всеми данными, фото 3×4 и сканы одним архивом.
- **«Генератор документов»**: документы Word из базы людей. Первый документ — **учётная карточка члена организации** по
  образцу из методички; чего не хватило в базе — вписывается тут же и дописывается в базу.
- Любой файл можно **перетащить в окно**: по пунктам спросит, что это за файл, что за скан и на чьё имя его закрепить, —
  и положит в личную папку человека (таблицу с анкетами — в рабочую папку и сразу откроет в «Проверке анкет»).
- **Справка** — методическое пособие ХРО МООО «РСО» по работе с документами ЛСО: оформление кандидата по шагам, пакет
  документов с образцами заполнения и сканов, названия папок и сканов для конкретного кандидата, учетная карточка, журнал
  учета, учебные заведения с кодами специальностей (приложения 1–5, с поиском и копированием).
- Светлая и тёмная тема, адаптивная вёрстка (ПК, Android, iPhone).
- Устанавливается как приложение (PWA), обновления проверяются по GitHub.

В тестовой ветке (`testing`) в корне лежит **[DocAssist.html](DocAssist.html)** — всё приложение одним файлом, собранное из текущего

## Ядро

### Рабочая папка

Пользователь выбирает папку — все данные живут в ней:

```
<Рабочая папка>/
  .docassist/                 ← служебные данные ядра
    workspace.json            ← паспорт папки
    variables.json            ← глобальные переменные
    outbox.json               ← предложения в общую базу
    base/*.json               ← база данных: древа «ключ:значение» (Адреса.json, Должность в СО.json…)
    people.json               ← база людей (проверенные данные)
    handout.json              ← откуда пришли файлы «Для выдачи» (чтобы вернуть на место)
  Анкеты 2025.xlsx            ← общие файлы — видны всем приложениям
  Для выдачи/                 ← временная папка: файлы, которые нужно отдать или куда-то загрузить
  Проверка анкет/             ← папка приложения
    rules.json                ← шаблоны и правила
    sessions/*.json           ← правки, отметки и пометки к таблицам (исходные файлы не меняются)
    Результаты/               ← готовые таблицы
    google.json               ← какие Google Таблицы открывались (связь снимка с таблицей)
    Google Таблицы/*.xlsx     ← снимки Google Таблиц для проверки
  Личные дела/
    cases.json                ← достижения, характеристики, подписи сканов, история переводов
    drive.json                ← Google Диск: древо папок, правила оформления, какие файлы где лежат
    templates.json            ← изменённые тексты документов
    Шаблоны/*.docx            ← свои бланки Word с метками {ФИО}…
    Фамилия Имя Отчество/     ← личная папка
      Фотографии/ Сканы/ Достижения/ Характеристика/
      Перевод 2026-09-01/     ← пакет перевода
  Генератор документов/
    settings.json             ← настройки (знак у «информ. рассылка»)
    Учетные карточки/*.docx   ← готовые карточки
```

Где папка физически лежит, решает адаптер хранилища:

| Режим | Где работает | Как попадают файлы |
|---|---|---|
| Папка на компьютере | Chrome, Edge, Яндекс Браузер, Opera **на ПК** | напрямую из папки |
| Хранилище браузера | везде, включая iPhone и Android | кнопки «Загрузить» / «Скачать» |

### Переносимость между версиями

Каждый служебный JSON хранится в «конверте»:

```json
{ "$type": "docassist/variables", "$version": 1, "$app": "0.1.0", "$savedAt": "…", "data": { … } }
```

- `$type` говорит любой версии, что лежит в файле.
- Миграции пишутся только для форматов, выпущенных в `main`: при изменении такого формата увеличивается `$version` и
  добавляется миграция `N → N+1` (`defineDocType`), старые файлы поднимаются до текущей версии.
- Форматы тестовых версий не переносятся: файл старой тестовой версии читается как пустой и перезаписывается.
  Тестовые версии зависят только от `main`, а не друг от друга.
- Изменения, которые задевают совместимость с `main`, всегда сопровождаются предупреждением (договорённость для сессий
  Claude — в [CLAUDE.md](CLAUDE.md)).
- Файл из **более новой** версии открывается только на чтение, чтобы старая версия его не испортила.
- Повреждённый файл не перезаписывается.

### Общий язык приложений

- `core/schema/fields.ts` — 35 полей анкеты РСО по порядку формы (`person.lastName`, `passport.series`, …) и варианты
  заголовков. Таблица без строки заголовков понимается по порядку столбцов.
- `core/base` — база данных: древа «ключ:значение». Узел существует только внутри родителя. Всё, что подтвердил
  пользователь, попадает в «Предложения в базу».
- `core/people` — база людей: проверенные данные по ФИО (для сверки и проверки уникальности). Кроме полей анкеты в
  записи могут быть поля вне анкеты (`EXTRA_FIELDS`: место работы, должность) — их дописывает «Генератор документов».
  Повторное сохранение из «Проверки анкет» такие поля не стирает.
- `core/variables` — глобальные переменные. В любом поле ввода по `Ctrl+Пробел` появляется список (`ui/VarSuggest.tsx`).
- `core/suggest` — словарь подсказок: что человек вводил в поле, подсказывается при наборе в таких же полях любого
  приложения. Поле участвует, если у него есть `data-field="person.firstName"` (поле общего языка) или `data-kind="name"`.

## Как добавить приложение

1. Создать папку `src/apps/<id>/`.
2. Добавить `manifest.ts`:

   ```ts
   import { lazy } from 'react';
   import { Table } from 'lucide-react';
   import type { AppManifest } from '@/core/registry/types';

   const manifest: AppManifest = {
     id: 'my-app',                 // постоянный идентификатор, менять нельзя
     title: 'Моё приложение',
     summary: 'Одна строка для карточки и меню',
     icon: Table,
     status: 'beta',               // 'stable' | 'beta' | 'soon'
     version: '0.1.0',             // при смене снова покажется бейдж «Обновлено»
     folder: 'Моё приложение',     // папка внутри рабочей папки
     requiresWorkspace: true,
     badges: [{ kind: 'new' }],    // «Новое!» — пока пользователь не откроет
     component: lazy(() => import('./MyApp')),
   };
   export default manifest;
   ```

3. Всё. Главная страница и бургер-меню подхватят приложение автоматически, а код загрузится только при открытии.

Окно для файлов, перетащенных в любое место сайта, приложение объявляет полем `fileDrop` манифеста (ленивый компонент
с `files` и `onClose`) — сейчас его даёт «Личные дела». Открыть это окно кнопкой (на телефоне перетаскивать нечем) —
`openIncomingFiles(files)` из `ui/FileDrop.tsx`; так работает «Добавить файлы» в списке бойцов «Личных дел».

Полям ввода с данными людей ставьте `data-field` (id поля из `core/schema/fields.ts`) и/или `data-kind` (тип переменной) —
тогда в них заработают подсказки из словаря, общие для всех приложений.

Служебные пункты меню лежат в `src/core/registry/menu.ts`, частые вопросы — в `src/content/faq.ts`, справка — в
`src/content/help/` (текст разделов — `src/pages/HelpPage.tsx`, учебные заведения — `institutions.ts`).

## «Проверка анкет»: как работает проверка

Каждый из 35 столбцов проверяет свой короткий **код на Lua** («Шаблоны и правила»). Сначала для каждой ячейки
выполняются **общие проверки** (только пробелы, «й» из двух символов, латиница в русских словах), потом — код столбца.

Обычному работнику код не нужен: код сам объявляет **настройки** — `setting.toggle("Галочка у каждого человека", true)`,
`setting.number("Курс до", 6)`, `setting.list("Варианты", {…})` — и они появляются переключателями и полями. Код открывается
отдельно: окно с номерами строк, подсказками по Ctrl+Пробел (функции, названия столбцов в `cell("…")`), шаблонами и
справкой по среде; ошибка в коде подсвечивает строку и объясняется по-русски. Рядом — «Проверить значение».

| Что есть в коде | Для чего |
|---|---|
| `value`, `field`, `confirmed`, `cell("Группа")` | значение ячейки; другие ячейки анкеты — `.value`, `.confirmed` (галочка «Проверено»), `.ok`, `.vars` |
| `problem` / `warning` / `notice` | ошибка / предупреждение (снимается галочкой) / совет; `{ fix = … }` — исправление |
| `confirm()`, `unique{ with = {…} }`, `remember` | галочка у каждого человека; уникальность по таблице и базе людей; значение для других ячеек |
| `setting.*` | регулировки в настройках столбца |
| `base.check`, `base.check_parts`, `base.has/list/find` | значение из базы (новое — «добавить в базу»), адрес по частям, чтение базы |
| `lib.*` | готовые функции: латиница/кириллица, `odd_letters` («й» из двух символов), даты, телефон, почта, маски, кавычки, СНИЛС/ИНН |

Lua работает в браузере через [fengari](https://fengari.io) (Lua 5.3 на JavaScript — офлайн и в одном HTML-файле), в
песочнице: без файлов и сети, бесконечный цикл обрывается. Код и настройки хранятся в `Проверка анкет/checks.json` —
только то, что изменено. Полная справка — вкладка «Справка» в приложении (`apps/anketa/lua/docs.ts`).

**Конструктор ячейки** — настройка в два пункта:

1. Порядок записи в древо: `2, 1, 3, *` — регион, индекс, район, а `*` — все оставшиеся по порядку после предыдущего
   числа. Индекс пишется первым, но хранится под регионом: тот же индекс в другом регионе — ошибка.
2. Части по порядку записи: описание (можно переписать), приписки — как в таблице, проверка части (готовая или своя
   функция из «Моей библиотеки»), «обязательно»,
   «только в одной ветке».

**Примеры значений** («Шаблоны и правила» → «Примеры значений») настраиваются: они показываются в подсказке «Пример: …»
у ошибки, в правилах и в конструкторе. По умолчанию — нейтральные заготовки («Фамилия», «01.01.2000», «000-000-000 00»,
«000000, Респ. Регион, р-н Районный, с. Примерное, ул. Примерная, д. 1»), а не чьи-то данные.

**Индивидуальное** (ФИО, дата рождения, паспорт, СНИЛС, ИНН, телефон, почта, ВК, курс, группа…) по умолчанию помечается
предупреждением и подтверждается **галочкой у каждого человека отдельно** (`confirm()` в коде, настройка «Галочка у каждого
человека»). Уникальные значения сверяются: повтор у другого
человека в таблице или в базе людей — ошибка.

**База сначала пустая.** Новые значения подтверждаются в анкете, разом кнопкой «Новые слова» или вручную на вкладке «База»
(тег + слово; если в слове есть приписка — предупреждение, что сохранится неправильно).

**Учебные заведения из справки.** «База данных» → «Учебные заведения из справки» → «Добавить в базу»: приложения 1–5 пособия
(все города или один) попадают в древо «Место учебы» — направления обучения внутри своего учебного заведения. Значения,
которые не проходят проверку столбца, не добавляются и перечисляются. «Направление обучения» по умолчанию сверяется со
списком своего места учебы (настройка «Своё для каждого места учебы») и принимает код специальности «00.00.00 Название»
или код профессии «00000 Название».

**«Проверить с актуальной информацией»** ищет человека в базе людей по ФИО: совпавшие поля отмечаются проверенными,
несовпавшие перечисляются. Анкета **готова**, когда нет ни ошибок, ни неподтверждённого; готовые можно сохранить в базу людей.

**Игнорировать** можно отдельное замечание, все замечания анкеты или всей таблицы (с подтверждением): они остаются видны
зачёркнутыми и не мешают готовности. Ошибки в коде проверки не игнорируются.

Таблицу можно открыть файлом или вставить через `Ctrl+V` (строки из Excel или Google Таблиц, заголовки не обязательны).
Исходный файл не меняется: правки хранятся отдельно, новая таблица собирается кнопкой «Новая таблица».

## «Личные дела»

**Ручной ввод.** «Добавить бойца» — ФИО и дата рождения (если такой человек уже есть в базе людей — предлагается открыть
его). На вкладке «Данные» — все 35 полей анкеты по разделам; под полями — подсказки формата (как ждёт «Проверка анкет» по
умолчанию: телефон `8(000)000-00-00`, СНИЛС с контрольным числом, ИНН, даты, «ёлочки» у отряда…) с кнопкой исправления и
предупреждение, если СНИЛС, ИНН, паспорт, телефон или почта уже есть у другого человека. Сохранять неполные данные можно.
Данные живут в общей базе людей (`.docassist/people.json`) — люди из «Проверки анкет» тоже видны в списке.

**Личная папка** «Личные дела/Фамилия Имя Отчество»: фотографии (основное — звёздочкой), сканы с подписью «что это»
(по имени файла угадывается: паспорт, СНИЛС…; видно, каких сканов не хватает), достижения (дата, уровень, файл грамоты),
характеристика (текст с заготовкой по данным бойца и подписанный скан). Если ФИО изменилось — папку можно переименовать.

**Файл — перетаскиванием в окно** (`ui/IncomingDialog.tsx`, `model/incoming.ts`): в любом месте сайта. Окно «Новый
файл» по пунктам: что за файл (скан, фото, грамота, характеристика, таблица с анкетами, другое) → что за скан → на чьё
имя (человек из базы людей или новый по ФИО — добавится в базу, личная папка создастся) → название и сохранение. Ответы
угадываются по имени файла. Файл ложится в раздел личной папки так же, как кнопкой «Добавить»: скан — с подписью и
именем по шаблону сканов, первое фото — основным, грамота — с записью о достижении; «Другое» — в саму личную папку
(блок «Другие файлы») или в рабочую папку. Несколько файлов — по очереди, у следующего тот же человек; «Сохранить все».

Со сканами (отмеченными галочками или всеми сразу):

- **Переименовать по шаблону** — имя файла из текста и меток данных человека: `{Документ} — {ФИО:кратко}` →
  «Паспорт (разворот с фото) — Примеров П. П.jpg». Метки скана: `{Документ}` (что это за скан), `{Имя файла}`
  (нынешнее имя), `{№}` (01, 02…); остальные — как в шаблонах документов (`{Фамилия}`, `{Дата рождения}`, `{Отряд}`…,
  глобальные переменные). Шаблон по умолчанию настраивается в «Шаблонах документов» → «Имена файлов сканов» и
  меняется прямо в окне переименования; расширение сохраняется, одинаковые имена получают номер. Подпись скана,
  основное фото и ссылки достижений переходят на новое имя.
- **В «Для выдачи»** — переместить (или скопировать) во временную папку `Для выдачи/` в рабочей папке, сразу с
  переименованием по шаблону. Вкладка «Для выдачи»: скачать файлы по одному или всё архивом, вернуть перемещённое в
  личную папку (с прежним именем и подписью), удалить, очистить папку.

**Перевод** одного бойца или нескольких сразу: новый отряд (РО, направление, должность — если меняются), дата, причина,
командиры. Пакет:

| Файл | Что это |
|---|---|
| `01 Заявление о переводе — Фамилия И. О.docx`, `02 Ходатайство…`, `03 Характеристика…` | тексты — из «Шаблонов документов» |
| `04 <свой бланк>…docx` | бланки Word из «Личные дела/Шаблоны» с заполненными метками |
| `05 Личная карточка…docx` | фото, все данные по разделам, достижения, переводы |
| `Фото 3×4 — …jpg` | основное фото, обрезанное до 3:4 |
| `Сканы/01 Паспорт (разворот с фото) — …jpg` | сканы с понятными именами (картинки сжимаются в JPEG до 2000 px) |
| `Данные — …xlsx` | 35 столбцов анкеты (открывается в «Проверке анкет») + столбцы перевода, карточка, достижения, документы |
| `Опись документов.docx` | список всего, что в пакете |

Пакет скачивается архивом и сохраняется в личную папку (`Перевод ГГГГ-ММ-ДД`; несколько бойцов — в `Личные дела/Переводы`).
«Перевод состоялся» записывает новый отряд в данные бойца.

**Метки** в шаблонах: `{ФИО}`, `{Дата рождения}`, `{Новый отряд}`, `{Дата перевода}`…, а также полные названия столбцов
анкеты и ключи глобальных переменных. Падеж — `{ФИО:кого}` (Примерова Примера Примеровича), `{Командир нового отряда:кому}`;
краткие формы — `{ФИО:кратко}` (Примеров П. П.), `{ФИО:подпись}` (П. П. Примеров); слово по полу — `{он|она}`. В своих бланках
Word метки находятся, даже если Word разбил их на куски; оформление сохраняется.

## «Генератор документов»: учётная карточка члена организации

Человек выбирается из базы людей (или вводится вручную), бланк Word заполняется по образцу из методического пособия
по работе с документами ЛСО (рисунок 1.12):

- Шаблон — `apps/doc-generator/member-card/template.docx` (бланк с 01.01.2026), встроен в приложение и работает офлайн.
  Значения пишутся в ячейки справа от подписей («ФИО», «Серия»…) — таблица и её сетка не меняются. Ячейки ищутся по
  подписям, поэтому обновлённый бланк с той же разметкой тоже подойдёт.
- Times New Roman 12; длинный адрес переносится в пустую строку под ним (после запятой, как в образце) — ширина текста
  считается по метрикам шрифта (`docx/measure.ts`). Что не помещается в строку, подсвечивается.
- У «информ. рассылка» квадрат из шрифта-символов заменяется знаком-символом: ✓ (или ☑, как в образце; без согласия — ☐).
- Чего не хватает в базе — подсвечено в форме, вписывается там же; «Дописать в базу» сохраняет вписанное в запись
  человека (недостающее — сразу, изменённое — по выбору). Подсказки к полям — по пособию, сокращённые наименования
  учебных заведений — из справки (`content/help/institutions.ts`), имя файла — `shortFio` из `content/help/manual.ts`.
- Файл: «Фамилия И.О. - Учетная карточка члена организации.docx» → `Генератор документов/Учетные карточки/` и скачивание.

## Google Диск и Google Таблицы

Всё общение с Google — в одном блоке `core/google` (остальные части обращаются к нему через `@/core/google`). Лимиты API
и обязательные проверки — в [CLAUDE.md](CLAUDE.md) → «Google API». Настройка проекта Google (Client ID, API-ключ, номер
проекта) — [docs/GOOGLE-SETUP.md](docs/GOOGLE-SETUP.md), значения вписываются в `src/core/google/config.ts`.

- **Доступ — узкий (`drive.file`):** приложение видит только файлы, которые создало само, и те, что человек выбрал в
  окне Google (Picker). Без проверки Google и без лимита пользователей. Доступ у каждого человека свой.
- **Только сайт и установленное приложение.** Версия-файл открывается с `file://` без адреса — Google её не пускает,
  кнопки Google там скрыты (`IS_SINGLE_FILE`).
- **Вход** — Google Identity Services: пропуск примерно на час, только в памяти вкладки; обновляется по нажатию.
- **«Личные дела» ↔ Диск** (`apps/lichnye-dela/drive`): человек подключает выданную папку и сам ведёт древо (создаёт
  папки, привязывает существующие, отмечает папки бойцов). Правила оформления — имя папки бойца по шаблону, имена и
  цвета папок разделов, имена сканов по шаблону. Сверка файлов по контрольным суммам (MD5) с историей сверки у каждого
  устройства: только здесь / изменён здесь / изменён на Диске / расхождение / только на Диске / удалён здесь. Миниатюры —
  только из файлов на устройстве.
- **«Проверка анкет» ↔ Таблицы** (`apps/anketa/google`): таблица читается одним запросом в снимок `.xlsx`, дальше —
  обычная проверка. «Обновить из Google» переносит правки и пометки к тем же людям (по ФИО), «Записать исправления» —
  только изменённые ячейки одним пакетом, как текст; строка ищется по ФИО, ячейку, изменённую в таблице, приложение не
  затирает — спрашивает. Пометки к ячейкам — только в приложении.
- **Личные настройки на личном Диске** (`core/sync`, по желанию): один файл, закрытый контрольной фразой (`core/vault`:
  ключ получается из фразы на устройстве, без фразы файл не открыть; в файле нет ни открытого текста, ни меток способа).
  Что переносить — группы: настройки приложений (`settingsFiles`), переменные, база данных, группы приложений
  (`syncGroups` в манифесте), по отдельному согласию — база людей и словарь. Бесспорное переносится сразу, спорное
  решает человек.
- **Расхождения** везде решаются одинаково (`core/device`, `ui/ConflictDialog.tsx`): у каждой версии — дата, время и
  устройство; человек выбирает верную и переписывать ли другую сторону.
- **Проверка безопасности** (`core/security`, страница «Google и безопасность»): https, адрес, чужая страница вокруг,
  посторонний код (в веб-версии его ещё и блокирует политика безопасности страницы — CSP из `vite.config.ts`), подмена
  функций отправки и шифрования, управление браузером программой, свой ли фоновый обработчик — и список того, что из
  браузера увидеть нельзя.

## Развёртывание

Ветка `testing` автоматически собирается и публикуется на GitHub Pages (`.github/workflows/deploy.yml`).
Один раз нужно включить: **Settings → Pages → Source: GitHub Actions**, а в **Settings → Environments → github-pages**
разрешить ветку `testing`.

После первого открытия сайт работает офлайн. Приложение раз в сутки сверяет свою версию с последним релизом на GitHub
(если релизов нет — с `package.json` в ветке `main`) и предлагает обновиться.

### Как выпустить релиз

Пошагово, с картинками в словах — [docs/RELEASE-GUIDE.md](docs/RELEASE-GUIDE.md). Коротко:

1. Поднять `version` в `package.json` и написать заметки в `docs/releases/vX.Y.Z.md`.
2. Выпустить релиз одним из способов:
   - на сайте GitHub: **Releases → Draft a new release → Choose a tag**: ввести `vX.Y.Z` (создать при публикации),
     выбрать ветку с кодом в **Target** → **Publish release**;
   - или из терминала: `git tag vX.Y.Z && git push origin vX.Y.Z`.

Workflow `.github/workflows/release.yml` прогонит тесты, соберёт версию-файл и веб-архив и прикрепит их к релизу
(заметки возьмёт из `docs/releases`, если описание релиза пустое).
