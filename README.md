# DocAssist

Веб-приложение для ускорения и автоматизации работы с документами РСО (Российских студенческих отрядов).
Набор отдельных «приложений» на общем ядре. Работает **локально и офлайн**: данные не покидают устройство.

- Первое приложение — **«Проверка анкет»**: загружаете таблицу анкет, приложение находит ошибки, слипшиеся слова,
  неверные адреса и предлагает исправления, а затем собирает новую таблицу.
- Светлая и тёмная тема, адаптивная вёрстка (ПК, Android, iPhone).
- Устанавливается как приложение (PWA), обновления проверяются по GitHub.

## Скачать

Готовые сборки — на странице [Releases](https://github.com/TOST2Q7/DocAssist/releases):

- **DocAssist-x.y.z.html** — всё приложение в одном файле: скачать и открыть двойным кликом в Chrome, Edge или
  Яндекс Браузере. Без установки и без интернета.
- **DocAssist-web-x.y.z.zip** — веб-версия для размещения на сервере (в любой папке), с офлайн-режимом и установкой как приложение.

## Структура

```
src/
  core/                 ← ЯДРО: общее для всех приложений
    storage/            ← хранилища: папка на ПК (File System Access) и хранилище браузера (IndexedDB)
    workspace/          ← рабочая папка, живые документы с автосохранением
    schema/             ← «общий язык»: версионированные документы, канонические поля, списки значений
    variables/          ← глобальные переменные (<fio>, <phone>…)
    dictionaries/       ← пользовательские дополнения справочников
    outbox/             ← «Предложения в базу» — пересылка новых слов разработчику
    tables/             ← чтение/запись xlsx, xls, ods, csv
    registry/           ← реестр приложений, бейджи, служебное меню
    update/             ← проверка новой версии на GitHub
  shared/               ← библиотеки для приложений
    address/            ← разбор и проверка адресов: типы, регионы, дерево населённых пунктов, шаблоны
    text/               ← пробелы, латиница в русских словах, кавычки, регистр, опечатки
  apps/                 ← ПРИЛОЖЕНИЯ: каждое в своей папке
    anketa/             ← «Проверка анкет»
    doc-generator/      ← пример будущего приложения (статус «Скоро»)
  pages/                ← служебные страницы (главная, рабочая папка, переменные, справочники…)
  ui/                   ← общие компоненты: шапка, бургер-меню, модальные окна, поле с переменными
  content/faq.ts        ← частые вопросы
```

## Ядро

### Рабочая папка

Пользователь выбирает папку — все данные живут в ней:

```
<Рабочая папка>/
  .docassist/                 ← служебные данные ядра
    workspace.json            ← паспорт папки
    variables.json            ← глобальные переменные
    outbox.json               ← предложения в общую базу
    dictionaries/*.json       ← дополнения справочников (адреса, списки)
  Анкеты 2025.xlsx            ← общие файлы — видны всем приложениям
  Проверка анкет/             ← папка приложения
    rules.json                ← шаблоны и правила
    sessions/*.json           ← правки к таблицам (исходные файлы не меняются)
    Результаты/               ← готовые таблицы
```

Где папка физически лежит, решает адаптер хранилища:

| Режим | Где работает | Как попадают файлы |
|---|---|---|
| Папка на компьютере | Chrome, Edge, Яндекс Браузер, Opera **на ПК** | напрямую из папки |
| Хранилище браузера | везде, включая iPhone и Android | кнопки «Загрузить» / «Скачать» |

### Переносимость между версиями

Каждый служебный JSON хранится в «конверте»:

```json
{ "$type": "docassist/variables", "$version": 1, "$app": "0.1.0", "$savedAt": "…", "data": { … } }
```

- `$type` говорит любой версии, что лежит в файле.
- При изменении формата увеличивается `$version` и добавляется миграция `N → N+1` (`defineDocType`).
  Старые файлы автоматически поднимаются до текущей версии.
- Файл из **более новой** версии открывается только на чтение, чтобы старая версия его не испортила.
- Повреждённый файл не перезаписывается.

### Общий язык приложений

- `core/schema/fields.ts` — канонические поля (`person.lastName`, `passport.series`, …) и варианты заголовков столбцов.
  Приложения сопоставляют столбцы таблиц с этими идентификаторами и обмениваются данными на общем языке.
- `core/schema/enums.ts` — встроенные списки значений (пол, должность, направление ЛСО…).
- `core/variables` — глобальные переменные. В любом поле `VarInput` можно выбрать сохранённое значение или написать `<ключ>`.
- `core/dictionaries` + `shared/address` — справочники. Всё, что добавил пользователь, попадает в «Предложения в базу».

## Как добавить приложение

1. Создать папку `src/apps/<id>/`.
2. Добавить `manifest.ts`:

   ```ts
   import { lazy } from 'react';
   import { Table } from 'lucide-react';
   import type { AppManifest } from '@/core/registry/types';

   const manifest: AppManifest = {
     id: 'my-app',                 // постоянный идентификатор, менять нельзя
     title: 'Моё приложение',
     summary: 'Одна строка для карточки и меню',
     icon: Table,
     status: 'beta',               // 'stable' | 'beta' | 'soon'
     version: '0.1.0',             // при смене снова покажется бейдж «Обновлено»
     folder: 'Моё приложение',     // папка внутри рабочей папки
     requiresWorkspace: true,
     badges: [{ kind: 'new' }],    // «Новое!» — пока пользователь не откроет
     component: lazy(() => import('./MyApp')),
   };
   export default manifest;
   ```

3. Всё. Главная страница и бургер-меню подхватят приложение автоматически, а код загрузится только при открытии.

Служебные пункты меню лежат в `src/core/registry/menu.ts`, частые вопросы — в `src/content/faq.ts`.

## «Проверка анкет»: строгая проверка

**Принцип: шаг влево/вправо — ошибка.** Для каждого поля по шаблону строится единственно правильная форма значения.
Значение верно, только если оно **в точности** совпадает с ней. Любое отличие — лишнее слово, точка, пробел, регистр,
порядок частей, другие кавычки — ошибка с подсветкой места и готовым исправлением. Поэтому ничего не проскакивает,
даже если для огреха нет отдельного правила (`src/shared/check/finalize.ts`).

Статусы поля:

| Статус | Что значит | Что делать |
|---|---|---|
| ✓ Верно | совпадает с шаблоном, всё подтверждено | — |
| ✗ Ошибка | не совпадает с шаблоном или нарушено правило | «Применить» / «Исправить по шаблону» |
| ⧉ Слиплось | слипшиеся слова — отдельная категория | то же |
| ? Подтвердить | автоматически проверить нельзя: новое село, улица, индекс, имя, отряд, учебное заведение, подразделение | проверить и «Подтвердить» — значение попадёт в справочник |
| ✓✓ Принято как есть | человек принял значение, не подходящее под шаблон | при изменении значения проверка вернётся |

Анкета **готова**, только когда нет ни ошибок, ни неподтверждённого. Кнопка «Новые слова» собирает всё
неподтверждённое по таблице в один список — подтверждение одним нажатием.

| Поле | Шаблон и проверки |
|---|---|
| Адреса и место рождения | шаблон адреса: порядок, разделитель, сокращения, обязательные и запрещённые части; сверка с деревом «регион → район → населённый пункт → улица», индексы региона и населённого пункта; лишние слова, слипшиеся слова |
| ФИО | только русские буквы, заглавная буква, двойные через дефис; имя и отчество — по справочнику (≈450 имён, отчества строятся автоматически); пол по имени и отчеству; форма фамилии |
| СНИЛС, ИНН | маска XXX-XXX-XXX XX и 12 цифр, контрольные суммы |
| Паспорт | серия (регион и год бланка), номер, код подразделения (регион, уровень), «Кем выдан» — по справочнику подразделений; выдача не раньше 14 лет; замена в 20/45 лет |
| Даты | ДД.ММ.ГГГГ (отметка времени — с чч:мм:сс), существование, будущие даты, возраст |
| Телефон, членский билет | маски (настраиваются): 8(XXX)XXX-XX-XX, XX-XX XXX |
| Почта, ВКонтакте | строчные буквы, опечатки доменов, неизвестный домен — подтвердить; https://vk.com/… |
| Отряд, учебное заведение, направление | «ёлочки», официальное название по справочнику, код направления ↔ название, курс ↔ уровень образования |
| Списки | точное значение из списка; закрытые списки (пол, форма обучения) не расширяются |
| Между строками | дубли СНИЛС, ИНН, паспорта — ошибка; телефона и почты — подтвердить |

Исходный файл не меняется: правки хранятся отдельно, новая таблица собирается кнопкой «Новая таблица»
(по умолчанию — только готовые анкеты). Все ячейки пишутся как текст — Excel не теряет ведущие нули.

## Развёртывание

Ветка `tests` автоматически собирается и публикуется на GitHub Pages (`.github/workflows/deploy.yml`).
Один раз нужно включить: **Settings → Pages → Source: GitHub Actions**, а в **Settings → Environments → github-pages**
разрешить ветку `tests`.

После первого открытия сайт работает офлайн. Приложение раз в сутки сверяет свою версию с последним релизом на GitHub
(если релизов нет — с `package.json` в ветке `main`) и предлагает обновиться.

### Как выпустить релиз

1. Поднять `version` в `package.json` и написать заметки в `docs/releases/vX.Y.Z.md`.
2. Выпустить релиз одним из способов:
   - на сайте GitHub: **Releases → Draft a new release → Choose a tag**: ввести `vX.Y.Z` (создать при публикации),
     выбрать ветку с кодом в **Target** → **Publish release**;
   - или из терминала: `git tag vX.Y.Z && git push origin vX.Y.Z`.

Workflow `.github/workflows/release.yml` прогонит тесты, соберёт версию-файл и веб-архив и прикрепит их к релизу
(заметки возьмёт из `docs/releases`, если описание релиза пустое).
