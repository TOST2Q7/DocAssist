# Как выложить готовое приложение в релизы

Памятка для выпуска новой версии DocAssist на GitHub — всё через сайт, без терминала.
Релиз — это страница на GitHub с готовыми файлами: `DocAssist-X.Y.Z.html` (всё приложение в одном файле) и
`DocAssist-web-X.Y.Z.zip` (для сервера). Файлы собирает GitHub сам — загружать их вручную не нужно.

## 1. Проверить, что версия готова

1. Откройте репозиторий → вкладка **Actions**. У последнего запуска для ветки `testing` должна быть **зелёная галочка**.
   Красный крестик — что-то сломано, выпускать рано (напишите мне, что за ошибка).
2. Откройте файл `package.json` в ветке `testing` и посмотрите строку `"version": "0.5.0"` — это номер версии.
   **Каждый новый релиз — новый номер** (0.5.0 → 0.5.1 для мелких правок, → 0.6.0 для заметных).
3. Убедитесь, что есть файл заметок `docs/releases/v0.5.0.md` (с тем же номером). Его текст станет описанием релиза.

> Номер версии и заметки я обновляю вместе с изменениями. Если хотите выпустить версию, а номер не менялся с прошлого
> релиза — попросите меня поднять версию.

## 2. (Рекомендуется) Перенести код в `main`

`main` — основная ветка: от неё считаются «выпущенные» форматы данных.

1. **Pull requests → New pull request**.
2. Вверху: `base: main` ← `compare: testing` → **Create pull request** → **Create pull request**.
3. Дождитесь зелёных проверок → **Merge pull request** → **Confirm merge**.

Если пропустить этот шаг, релиз можно собрать прямо из `testing` (см. ниже «Target»).

## 3. Создать релиз

1. Справа на главной странице репозитория — **Releases** → кнопка **Draft a new release**
   (или **Create a new release**).
2. **Choose a tag** → впишите `v0.5.0` (буква `v` + номер из `package.json`, точь-в-точь) → нажмите
   **Create new tag: v0.5.0 on publish**.
3. **Target** — ветка, из которой собирать: `main` (если сделали шаг 2) или `testing`.
4. **Release title** — например, `DocAssist v0.5.0`.
5. **Описание можно оставить пустым** — подставится из `docs/releases/v0.5.0.md`.
6. Нажмите **Publish release**.

## 4. Дождаться файлов

1. Вкладка **Actions** → запуск **«Релиз»**. Он идёт 3–5 минут: тесты, сборка, упаковка.
2. Когда появится зелёная галочка, откройте релиз — внизу, в **Assets**, будут:
   - `DocAssist-0.5.0.html` — для компьютера: скачать и открыть двойным кликом;
   - `DocAssist-web-0.5.0.zip` — для сервера;
   - `SHA256SUMS.txt` — контрольные суммы.
3. Всё. Приложение у пользователей само предложит обновиться: раз в сутки оно сверяет версию с последним релизом.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| В «Релиз» красный шаг **«Проверка версии»** | Тег не совпал с `package.json` (например, тег `v0.5.0`, а в файле `0.4.0`). Удалите релиз и тег (ниже), исправьте номер и повторите. |
| Красный шаг с тестами или сборкой | Код сломан. Удалите релиз и тег и напишите мне, что за ошибка (откройте запуск → красный шаг → текст). |
| Релиз есть, а файлов в Assets нет | Подождите окончания «Релиз» в Actions. Если запуска нет совсем — удалите релиз с тегом и опубликуйте заново. |
| Опубликовали не тот номер | Удалите релиз и тег, опубликуйте с правильным. |

**Как удалить релиз и тег:** Releases → нужный релиз → значок корзины (**Delete**) → подтвердить. Потом откройте
страницу тегов `https://github.com/TOST2Q7/DocAssist/tags`, у нужного тега — меню «…» → **Delete tag**.

## Шпаргалка

1. Actions — зелёное.
2. `package.json` — новый номер, есть `docs/releases/vНОМЕР.md`.
3. (Желательно) Pull request `testing` → `main`, Merge.
4. Releases → Draft a new release → тег `vНОМЕР` (create on publish) → Target → Publish.
5. Actions → «Релиз» зелёный → в релизе появились файлы.
