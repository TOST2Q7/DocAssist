# Как подключить DocAssist к Google

Чтобы «Личные дела» работали с Google Диском, а «Проверка анкет» — с Google Таблицами, приложению нужен свой проект в
Google Cloud: в нём Google записывает, что такое DocAssist, с какого адреса он работает и какой доступ просит.
Настраивается один раз, бесплатно (банковская карта не нужна), минут за 20.

На выходе будут три значения — их нужно вписать в `src/core/google/config.ts`:

| Что | Как выглядит | Где взять |
|---|---|---|
| **Client ID** | `1234567890-abc…xyz.apps.googleusercontent.com` | шаг 4 |
| **API-ключ** | `AIzaSy…` (39 знаков) | шаг 5 |
| **Номер проекта** | `1234567890` (только цифры) | шаг 6 |

Все три значения **не секретные**: Google пустит вход только с адресов, вписанных в проект, а ключ ограничен адресом
сайта. Их можно хранить прямо в коде и коммитить. **Секрет клиента (Client secret) не нужен** — нигде его не сохраняйте и
никому не пересылайте.

> Совет: заведите для проекта отдельный Google-аккаунт (например, `docassist.ваш-штаб@gmail.com`) и сделайте вторым
> владельцем проекта свой личный аккаунт. Тогда проект не потеряется, если кто-то уйдёт.

---

## Шаг 1. Создать проект

1. Откройте <https://console.cloud.google.com/> и войдите в аккаунт, который будет владельцем проекта.
2. Вверху — выбор проекта → **«Новый проект» (New project)**.
3. Название: `DocAssist`. Организация — «Без организации» (No organization). **Создать**.
4. Убедитесь, что вверху выбран именно этот проект.

Если консоль предлагает «бесплатный пробный период» с картой — отказывайтесь: для Диска, Таблиц и окна выбора оплата не
нужна.

## Шаг 2. Включить три API

Меню ☰ → **APIs & Services (API и сервисы) → Library (Библиотека)**. Найдите по очереди и нажмите **Enable (Включить)**:

1. **Google Drive API** — файлы и папки на Диске;
2. **Google Sheets API** — чтение и запись Google Таблиц;
3. **Google Picker API** — окно выбора файлов Google.

## Шаг 3. Экран согласия (что человек увидит при входе)

Меню ☰ → **Google Auth Platform** (в старом виде консоли — **APIs & Services → OAuth consent screen**). Если просит
«Get started» — нажмите и пройдите мастер.

**Branding (Оформление):**
- App name: `DocAssist`.
- User support email: почта, на которую могут написать пользователи.
- Логотип **не загружайте**: с логотипом Google требует проверку бренда. Без него всё работает.
- Ссылки на домашнюю страницу и политику конфиденциальности можно оставить пустыми (для нашего узкого доступа они не
  обязательны). Если захотите заполнить — домашняя страница `https://tost2q7.github.io/DocAssist/`.
- Developer contact: ваша почта.

**Audience (Аудитория):**
- User type: **External (Внешние)** — у людей личные аккаунты Gmail.
- Сначала проект в режиме **Testing (Тестирование)**: войти смогут только почты из списка **Test users** (до 100).
  Добавьте туда себя и пару человек для проверки.
- Когда всё проверите — **Publish app (Опубликовать)** → статус **In production**. Проверка Google для нашего доступа
  не нужна, лимита пользователей нет, предупреждения «Приложение не проверено» не будет.

**Data access (Доступ к данным) → Add or remove scopes:**
отметьте три пропуска (все — «неконфиденциальные», non-sensitive):

| Пропуск | Зачем |
|---|---|
| `openid` | вход |
| `.../auth/userinfo.email` | показать, под какой почтой вы вошли |
| `.../auth/drive.file` | **только** файлы, которые приложение создало само или которые человек выбрал в окне Google |

Других пропусков не добавляйте. Полный доступ к Диску (`drive`, `drive.readonly`) и ко всем таблицам (`spreadsheets`)
потребовал бы проверки Google, лимита в 100 человек и платного аудита — DocAssist устроен так, чтобы он не был нужен.

## Шаг 4. Client ID (вход)

**Google Auth Platform → Clients → Create client** (или APIs & Services → Credentials → Create credentials →
OAuth client ID):

1. Application type: **Web application (Веб-приложение)**.
2. Name: `DocAssist web`.
3. **Authorized JavaScript origins (Разрешённые источники JavaScript)** — адреса, с которых разрешён вход. Без пути и без
   косой черты в конце:
   - `https://tost2q7.github.io` — сайт на GitHub Pages;
   - `http://localhost:5173` — для разработки (`npm run dev`);
   - `http://localhost:4173` — для проверки сборки (`npm run preview`).

   Адреса `localhost` нужны только для разработки. Надёжнее завести для них **отдельный Client ID** (или отдельный
   тестовый проект), а в рабочем оставить только `https://tost2q7.github.io`: иначе любая программа на компьютере,
   поднявшая сайт на этих портах, сможет просить вход от имени DocAssist.
4. **Authorized redirect URIs** — оставьте пустым (вход идёт во всплывающем окне).
5. **Create** → скопируйте **Client ID**. Client secret не нужен.

Если DocAssist будет размещён ещё где-то (веб-архив на своём сервере, свой домен), добавьте сюда и этот адрес — иначе
Google там вход не пустит. Версию-файл (`DocAssist.html`, открытие двойным кликом) добавить нельзя: у неё нет адреса,
поэтому в ней Google и выключен.

## Шаг 5. API-ключ (окно выбора файлов)

**APIs & Services → Credentials → Create credentials → API key.** Скопируйте ключ и сразу ограничьте его
(**Edit API key**):

- **Application restrictions → Websites (HTTP referrers)**, адреса:
  - `https://tost2q7.github.io/*`
  - `http://localhost:5173/*`
  - `http://localhost:4173/*`
- **API restrictions → Restrict key → Google Picker API** (только его).
- **Save**.

## Шаг 6. Номер проекта

**☰ → IAM & Admin → Settings** (или главная страница проекта, карточка «Project info») → **Project number** — только
цифры. Не путайте с Project ID (там буквы). Без номера окно выбора откроется, но приложение не получит доступ к
выбранным файлам.

## Шаг 7. Вписать значения в приложение

`src/core/google/config.ts`:

```ts
export const GOOGLE_CLIENT_ID = '1234567890-abc…xyz.apps.googleusercontent.com';
export const GOOGLE_API_KEY = 'AIzaSy…';
export const GOOGLE_APP_ID = '1234567890';
```

Можно просто прислать эти три значения в сессию Claude — их впишут, пересоберут и отправят в ветку `testing`.

## Шаг 8. Опубликовать сайт

1. На GitHub: **Settings → Pages → Source: GitHub Actions**.
2. **Settings → Environments → github-pages → Deployment branches**: разрешите ветку `testing`.
3. После пуша в `testing` дождитесь зелёного запуска «Тесты и публикация» во вкладке **Actions** (задача `deploy`).
4. Сайт: <https://tost2q7.github.io/DocAssist/>.

## Шаг 9. Проверить

1. Откройте сайт (лучше в обычном окне Chrome, не в режиме инкогнито) → меню → **«Google и безопасность»** →
   **«Войти в Google»**. Откроется окно Google: выбор аккаунта и экран согласия «DocAssist хочет… просматривать,
   изменять, создавать и удалять только те файлы Google Диска, которые вы используете в этом приложении». Галочку
   доступа к Диску нужно оставить.
2. Там же — **«Проверка безопасности устройства»**: всё зелёное (кроме пунктов, честно помеченных как недоступные).
3. **«Личные дела» → «Google Диск» → «Выбрать папку на Google Диске»** — выберите выданную папку. Создайте папку внутри,
   откройте бойца → «Личная папка» → «Создать по правилам», добавьте скан → «Отправить на Диск». Откройте папку на
   Диске (ссылка в панели) — файл на месте, папки нужного цвета.
4. **«Проверка анкет» → «Из Google Таблиц»** — откройте тестовую таблицу, исправьте ячейку, «Записать исправления».
5. **Личные настройки:** «Google и безопасность» → «Включить и сверить» → придумайте фразу. На другом устройстве или в
   другом браузере: войдите тем же аккаунтом → «Включить и сверить» → фраза → настройки и древо Диска приехали.

## Как админ выдаёт папку

Google Диск → папка → **«Открыть доступ»** → почта человека → роль **«Редактор»** → «Отправить». У человека папка
появится в **«Доступные мне»** — её он и выбирает в DocAssist. С правами «Читатель» или «Комментатор» приложение ничего не
сможет создать и сообщит об этом.

Файл, загруженный человеком, принадлежит ему и занимает место в его 15 ГБ. Если важно, чтобы файлы оставались у штаба,
владелец папки может принимать передачу владения или со временем перейти на общий диск (Google Workspace).

## Если что-то не так

| Что видно | Почему | Что сделать |
|---|---|---|
| «Ошибка 400: origin_mismatch» / «redirect_uri_mismatch» | Адреса сайта нет в Authorized JavaScript origins (шаг 4) | Добавьте точный адрес: `https://`, без пути и косой черты в конце. Изменения применяются за 5–30 минут |
| «Доступ заблокирован: приложение не прошло проверку» / `access_denied` | Проект в режиме Testing, а почты нет в Test users | Добавьте почту в Test users или опубликуйте приложение (шаг 3) |
| «Браузер не открыл окно Google» | Заблокированы всплывающие окна | Разрешите всплывающие окна для сайта (значок в адресной строке) |
| Окно выбора: «The API developer key is invalid» | Ключ ограничен не теми адресами или Picker API не включён | Проверьте шаг 2 и шаг 5 |
| Файл выбран, но «Этот файл ещё не показан приложению» | Неверный номер проекта (шаг 6) или файл показан другим аккаунтом | Проверьте `GOOGLE_APP_ID`; выберите файл ещё раз под своим аккаунтом |
| «Нет прав на это действие на Google Диске» | У человека права «Читатель» на папку | Админ выдаёт права «Редактор» |
| «Google просит подождать» | Сработал лимит запросов | Подождать минуту; приложение и само повторяет с паузой |
| В версии-файле нет кнопок Google | Так и задумано: у файла нет адреса | Установите приложение с сайта («О программе» → «Установить приложение») |

## Лимиты и наблюдение

- Таблицы: 300 запросов в минуту на весь проект (общие для всех людей), 60 — на человека. DocAssist читает таблицу
  одним запросом и записывает исправления одним пакетом, поэтому этого хватает с большим запасом.
- Диск: около 12 000 запросов в минуту на человека; массовые загрузки идут очередью.
- Сколько запросов и ошибок — **APIs & Services → Dashboard** (графики по каждому API).
- Подробно и с выводами для кода — `CLAUDE.md` → «Google API».

## Безопасность

> **Важно: адрес `tost2q7.github.io` общий для всех сайтов GitHub Pages аккаунта TOST2Q7.** Если у аккаунта есть другие
> репозитории с включённым Pages (или репозиторий `tost2q7.github.io`), их страницы для браузера — тот же сайт: они
> видят хранилище браузера DocAssist (данные людей в режиме «Хранилище браузера», запомненный ключ личных настроек)
> и могут просить вход в Google от имени DocAssist. Варианты:
> - не включать Pages ни в одном другом репозитории этого аккаунта (проверьте Settings → Pages у остальных);
> - лучше — отдельная организация GitHub только для DocAssist (адрес станет `имя-организации.github.io`) или свой
>   домен. При переезде поменяйте адреса в Client ID и в ограничениях ключа.

- Ключи в коде — нормально: они не дают доступа к данным, а только говорят Google, что это DocAssist.
- Включите двухэтапную проверку в Google-аккаунте владельца проекта и в GitHub. Кто может менять ветку `testing`,
  тот может изменить приложение у всех пользователей (оно обновляется само) — защитите ветку (Settings → Branches).
- Client secret не нужен и не должен появляться в коде.
- Копия DocAssist на чужом адресе не сможет войти в Google от имени DocAssist: адреса не совпадут.
- Если переезжаете на другой адрес (свой домен), добавьте его в Client ID и в ограничения ключа. Данные браузера и
  установка привязаны к адресу: на новом адресе приложение начнёт «с чистого листа» (рабочая папка на компьютере и
  личные настройки на Google Диске при этом сохраняются).
