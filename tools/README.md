# Помощник `da` — работа с репозиторием на Mac

Меню в Терминале для повседневной работы: обновить ветку, сохранить и отправить изменения, переключить ветку,
влить одну ветку в другую, сделать Pull Request, **выпустить релиз** с описанием из `docs/releases/vX.Y.Z.md`.
Каждое действие показывает команду git, которую выполняет, — видно, что происходит.

## Установка (один раз)

1. Установите Homebrew, если его нет: <https://brew.sh>.
2. В Терминале:
   ```bash
   brew install gh node        # GitHub CLI (релизы, Pull Request) и Node.js (сборка, проверки)
   gh auth login               # войти в GitHub: GitHub.com → HTTPS → Login with a web browser
   cd путь/к/DocAssist
   ./tools/install.sh          # команда «da» в Терминале из любой папки
   ```
3. Откройте новое окно Терминала и наберите `da` — откроется меню.
   Или дважды щёлкните **`tools/DocAssist.command`** в Finder.

Проверить, всё ли установлено: `da doctor`.

## Меню

| № | Что делает |
|---|---|
| 1 | Состояние: ветка, что изменено, что не отправлено, последние коммиты |
| 2 | Обновить ветку с GitHub. Если есть и ваши, и чужие коммиты — сливает их (история не переписывается) |
| 3 | Сохранить изменения: всё или выбранные файлы, с коротким описанием; потом предложит отправить |
| 4 | Отправить на GitHub. Если там появились чужие коммиты — предложит сначала обновиться |
| 5 | Обновить и отправить разом |
| 6 | Ветки: переключиться (в том числе на ветку, которая есть только на GitHub), создать, удалить |
| 7 | Влить другую ветку в текущую (например, `main` в `testing`) |
| 8 | Pull Request: создать (`testing → main`), список, открыть в браузере |
| 9 | **Релизы** — см. ниже |
| 10 | Собрать `DocAssist.html` и открыть; проверки (типы и тесты); запуск для разработки |
| 11 | История коммитов |
| 12 | Проверить окружение (git, автор коммитов, gh, node) |

Несохранённые изменения не теряются: если они мешают обновиться или переключить ветку, помощник предложит спрятать
их на время (`git stash`) и вернуть.

**Конфликт** (одно и то же место изменено и у вас, и на GitHub): помощник покажет файлы и предложит открыть их,
отменить слияние или разобраться самому. Если конфликт только в `DocAssist.html` — пересоберёт его сам.

## Релизы (`da release`)

1. **Новая версия** — поднимает номер в `package.json` (предложит 0.6.0 → 0.6.1 / 0.7.0 / 1.0.0), создаёт черновик
   описания `docs/releases/vX.Y.Z.md`, открывает его на правку, сохраняет и отправляет.
2. **Написать или поправить описание** — открывает `docs/releases/vX.Y.Z.md` текущей версии.
3. **Выпустить релиз** — проверяет и выпускает:
   - тега `vX.Y.Z` ещё нет на GitHub;
   - есть описание (и в нём не остался текст черновика);
   - всё сохранено и отправлено, а версия в выбранной ветке на GitHub совпадает с `package.json`;
   - по желанию прогоняет проверки (типы и тесты);
   - показывает итог и после «да» создаёт релиз: `gh release create vX.Y.Z --notes-file docs/releases/vX.Y.Z.md`.
   Файлы релиза (`DocAssist-X.Y.Z.html`, веб-архив) собирает GitHub за 3–5 минут — помощник может следить за сборкой.
   Если `gh` не установлен, релиз выпускается через тег — GitHub создаст его сам с тем же описанием.
4. **Обновить описание уже выпущенного релиза** — из того же md-файла.
5. **Посмотреть сборку**, **список релизов**, **удалить релиз** (вместе с тегом — если выпустили по ошибке).

## Команды без меню

```bash
da status            da pull            da push            da sync
da commit "текст"    da branch          da merge           da pr
da release           da version         da notes           da build
da log               da doctor          da help
```

Работает в bash 3.2 (стоит на macOS) и новее; нужен только git, для релизов и Pull Request — `gh`, для сборки — `node`.
